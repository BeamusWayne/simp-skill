## P5 独立运行

1. 固定模型版本、宿主版本、权限、预算和采样参数。无 skill、旧 skill、新 skill 各用独立会话与目录，获得相同原始材料/已授权历史，不共享答案。旧/新版分别使用各自工具；端到端差异不能单独归因于提示词。
2. 先跑调试集，规则冻结后跑留出集。每例每组三次，24 × 3 × 3 = 216 次，多轮案例整段计一次。若使用留出结果调参，补充新的留出案例再验收。
3. 部分案例额外向无 skill 组提供同一规范化输入，用于判断指令是否有独立价值。不能把工具整理材料的优势都计为提示词优势。
4. 每次记录 case_id、split、group、repeat、model/version、host/version、skill_commit、tool_commit、工具调用、最终答案、tokens、耗时、人工 rubric 和关键错误。私密或完整运行日志放 evals/runs（忽略），仅合成且脱敏摘要可提交。
5. 由不知道分组的评审按 rubric.md 评分；关键分歧人工复核，不依赖单个“裁判模型”的总分。当前 manual-walkthrough.md 是作者走查示例，不是盲测或独立模型结果。

发布门槛：身份颠倒、编造来源、拒绝解释为同意、草稿当已执行、未授权持久化等关键错误为零；正确性和实用性相对 v1 改善、相对无 skill 不退步；简单请求不增加无关工具/追问。报告实际差异与波动，不用小样本宣称统计显著。自动测试全部通过，Windows/Linux CI、迁移恢复演练和目标宿主安装验证完成后才讨论 v2.0 发布。
